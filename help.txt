Usage: ice9-bluetooth <-f <file.fc32> | -l> <-a | -c <center-freq> -C <chan>>
Captures Bluetooth packets using a HackRF, bladeRF, or USRP SDR.

Mandatory arguments:
    -f, --file=FILE         read input from fc32 file (cfile)
    -l, --capture           capture live (cannot combine with -f)

    -a, --all-channels      all-channel sniffing (requires bladeRF 2.0)
            or
    -c, --center-freq=FREQ  center frequency (in MHz)
    -C, --channels=CHAN     number of channels to capture (>= 4, divisible by 4)

Optional arguments:
    -w, --fifo=OUTPUT       output pcap to OUTPUT (may be a pcap file or FIFO)
    -r, --check-crc         validate BLE CRC-24 and set PCAP flags
    -s, --stats             print performance stats periodically
    -v, --verbose           print detailed info about captured bursts
    -i IFACE                which SDR to use, example: hackrf-1234abcd
    -I, --install           install into Wireshark extcap folder
    -Z, --zmq=ENDPOINT      stream packets to collector (e.g. tcp://collector:5555)
    -K, --zmq-curve-key=FILE  enable CURVE encryption using key file
    -G, --gpsd              tag packets with GPS coordinates from gpsd
        --sensor-id=NAME    sensor identity for multi-sensor deployments

GPU acceleration:
    When built with OpenCL support, the polyphase filterbank channelizer and
    FFT are offloaded to the GPU automatically. No flags are needed. Falls
    back to FFTW on systems without OpenCL.

Channel count notes:
    The PFBCH2 channelizer works best with certain channel counts. Recommended
    values are 40, 48, and 60. Other counts (e.g. 44, 52, 56) may produce poor
    CRC validation rates due to characteristics of the filterbank at those sizes.

GPS tagging (requires libgps):
    When --gpsd is active, each packet is tagged with the latest GPS fix from
    gpsd. PCAP files use PPI headers (DLT 192) with GPS coordinates. ZMQ
    streams use multipart messages (GPS frame + PCAP record). Subscribers
    can write GPS-tagged PCAPs using --gps flag.
    Example:
        ice9-bluetooth -l -i usrp-... -C 40 --gpsd -w capture.pcap
    With ZMQ:
        ice9-bluetooth -l ... --gpsd --zmq tcp://collector:5555
        python3 tools/zmq_subscriber.py tcp://*:5555 -w output.pcap --gps

ZMQ packet streaming (requires libzmq):
    Publishes each captured BLE/BT packet as a PCAP record over a ZMQ PUB socket.
    Subscribers receive the standard PCAP packet header + RF Info header + payload.
    Use for distributed sensors, remote monitoring, or custom tooling.

    Sensors always connect out to a central collector (dashboard or subscriber).
    The collector binds and receives data from one or more sensors. A C2 control
    channel (DEALER/ROUTER) is automatically established on data_port + 1.

    Example:
        python3 tools/zmq_web_dashboard.py tcp://*:5555
        ice9-bluetooth -l -c 2441 -C 40 --zmq tcp://collector:5555
        ice9-bluetooth -l -c 2441 -C 40 --zmq tcp://collector:5555   # more sensors
    Encrypted:
        python3 tools/zmq_keygen.py server.key
        ice9-bluetooth -l ... --zmq tcp://collector:5555 --zmq-curve-key server.key

This tool also supports the Wireshark extcap interface:
    ice9-bluetooth --extcap-interfaces
    ice9-bluetooth --extcap-interface=INTERFACE --extcap-dlts
    ice9-bluetooth --extcap-interface=INTERFACE --extcap-config
    ice9-bluetooth --extcap-interface=INTERFACE --fifo=PATH_FILENAME --capture
